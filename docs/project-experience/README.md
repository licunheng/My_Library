# 项目经验

存放做过的项目里值得以后复用的记录。一篇经历一个 Markdown 文件，不另建代码工程。

## 命名

```
docs/project-experience/YYYY-MM-short-title.md
```

- `YYYY-MM`：项目主要发生或收尾的年月。
- `short-title`：英文小写，单词用连字符，能看出主题即可。例如 `2026-03-motor-driver-bringup.md`。

文件从 [`_template.md`](_template.md) 复制。模板本身留在目录里，不要往模板里填真实项目。

## 每篇写什么

按模板的六节写：背景、角色、技术栈、难点、结果、可复用结论。

- 背景说明要解决的问题和约束。
- 角色写自己负责的范围。
- 技术栈点出芯片、工具和协议，具体手册仍放在 `docs/chips/`，这里用路径互相引用。
- 难点写判断过程和最后的处理，而不只写结论。
- 结果写做到什么程度，用现象或数据说明。
- 可复用结论写下次能直接沿用的做法和判断标准。

某一节确实没有内容时写「无」，或删掉该节。

## 可以写进仓库的范围

保留可公开的技术事实、自己的判断和复盘。账号、令牌、私钥、密码，以及未获同意公开的客户名称和数据，不要出现在正文、文件名或提交说明里。
